How it works

1 · PostA poster signs a predicate with holes — a pure, sandboxed check whose free variables (the witness) a solver must fill — plus a reward and deadline.
2 · SolveA solver submits only values. The platform composes witness literals + the poster's predicate, byte-for-byte. The solver never touches the logic — the payout can't be gamed.
3 · SettleThe composed check runs through the same gate every Voda fact takes: non-vacuous, machine-stable across seeds, re-runs True. Iff it passes, a signed proof Drop is minted and the reward releases minus a 5% take-rate.
4 · Re-runAnyone downloads the proof and re-runs it themselves. The referee is math — the escrow key can't fake a settlement.

Re-run a proof yourself

Every settled bounty's proof is an ordinary check-grounded Drop in the escrow pond (pond/). Verify it with Voda's single-file, stdlib-only verifier — nothing to install:

curl -sLO https://voda.onl/lake/sava_verify.py
curl -sL "$BOARD/pond/drops/settle-<bounty-id>.json" -o proof.json
python3 sava_verify.py drop proof.json --trust <escrow-pubkey> --execute-checks --json   # exit 0 = it re-derives

The check you re-run is exactly the solver's witness literals followed by the poster's predicate. Open board.json, compare — that's the whole trust model.
